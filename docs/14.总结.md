# 14. 总结

## 这个项目的形状

一个把多个 AI 账号统一成 OpenAI 接口的 Android 应用。

```
客户端 ──→ 网关（本地 8790）──→ 多家上游
              │
              ├─ 标签路由：写哪家发哪家
              ├─ 选号：按优先级与余额
              ├─ 容错：冷却 / 禁用 / 熔断 / 换号
              └─ 记录：调用明细与运行日志
```

## 五条不可动摇的设计原则

### 1. Provider 的边界是「OpenAI 进、OpenAI 出」

上游协议细节不泄漏到网关层。这是可维护性的根基：加一家只写一个 Provider，
其余全部自动获得。

### 2. 标签是唯一路由依据

不查目录、不推断名称、不兜底给别家。写 `腾讯国内/x` 只会发到腾讯。

标签表是**一张表，中文是正名、英文是别名**：输入两种都认，输出只出中文
（`/v1/models` 与模型页永远显示中文前缀）。英文别名只是为「把 model 放进 HTTP 头」
的 ASCII-only 客户端准备的兼容入口，不构成第二套命名体系。

### 3. 默认不做跨供应商转移

「换到别家」会打破用户「写哪家发哪家」的预期，所以默认关闭，要开必须手动配候选。

### 4. 未知 ≠ 零

额度查不到时显示「—」，不显示 0。0 会让人以为真的用完了，白充钱。

### 5. 失败要如实说

不把「地址拼错」说成「没有这个模型」，不把「空响应」说成成功，
不把「上游只吃流式」的 400 说成模型挂了。

## 最容易踩的五个坑

### 1. Base URL 别先剥版本段

`joinBaseAndPath()` 保留用户写的 `/v1`，只补缺的那一段。
先剥再贴会把中转站拼成 `/chat/completions`，上游回
`The requested endpoint was not found`。

### 2. 模型测试要按类型打端点

拿对话请求打生图 / 向量 / 重排端点，上游一律 400。
识别顺序：上游能力字段 → id 词根；重排必须排在向量前面。

### 3. 自定义名不能写进凭证

昵称会被上游覆盖。`customName` 单独存在状态文件里，
`setCustomName()` 不碰凭证。

### 4. 嵌 WebView 的弹窗要关滚动

`AppDialog` 默认的 `verticalScroll` 会抢走滑块手势。

### 5. 额度池不是账号属性（Cline）

腾讯/字节的「区域」是账号属性（一个号只属于一个站），所以用 `RegionAwareSupport`。
但 Cline 的「额度池」不是 —— **同一个令牌两池都能打**，池是模型走哪条计费通道。

混用会出三个错：为两池各拉一次目录、该池没账号就不生成分组、硬筛账号。
正确做法是**一个 provider + 模型 id 前缀**，选号不做任何池过滤。

判据很简单：**这个维度换了之后，账号本身还成不成立？**
成不成立（一个号能打两个池）→ 不是账号属性，别塞进 `RegionAwareSupport`。

### 6. 导入导出只放行语义确定的旧版本

v1/v2 缺启用开关与优先级，补默认值会改掉用户策略 → 拒绝。
v3 只缺自定义名，缺失含义唯一 → 放行。

## 改动守则

1. **改前先读本文档体系**，尤其是 [04.供应商协议层.md](04.供应商协议层.md)
   与 [08.上游陷阱清单.md](08.上游陷阱清单.md)
2. **保持 `:core:test` 全绿**
3. **新增供应商三步**：`core` 实现 `Provider` → `ProviderBootstrap` 登记 →
   `app` 实现并登记 `ProviderUi`，再在标签表加一条
4. **每改一次功能，同步更新对应 doc**，不要留着过时描述
5. **提交信息里不出现被测应用的名字、包名、签名主体**
6. **新增 `AppUiState` 字段要改四处**：`AppUiState` / `Snapshot` / `Snapshot(...)` 调用 /
   `refresh()` 里的 `current.copy(...)`。漏掉第四处**编译不报错**（`copy` 有默认值），
   表现是「界面永远看不到这次改动」。详见 [16.自动签到.md](16.自动签到.md)。
7. **修 bug 前先回答**：这个 bug 在已知的最后一个全绿版本存在吗？
   - 不存在 → 是之后某次改动引入的。**先 git diff 找到引入点，恢复原行为，
     再考虑要不要保留新特性**。不要在引入 bug 的代码上继续叠补丁。
7. **任何触碰 `refreshAccount` / `classify` 的改动**：先重读
   [08.上游陷阱清单.md](08.上游陷阱清单.md) 的凭证铁律。Antigravity 的凭证策略
   已被验证过一次错误方向，不要用「看起来更健壮」的理由再踩一遍。
8. **告警纪律**：账号/额度类告警走 `GatewayEngine.quotaAlerts`，App 侧由
   `QuotaAlertNotifier` 统一做震动 + 通知。三级语义不得混淆：
   `ACCOUNT_EXHAUSTED`（换号成功，轻提醒）、`PROVIDER_EXHAUSTED`（没钱了，指向充值）、
   `ALL_ACCOUNTS_DISABLED`（账号被关/失效，**指向启用或重新登录，不是充值**）。
   告警只做展示，**不得参与任何调度决策**。
9. **外部来源必须可追溯**：上游协议细节、UI 动效参数凡参考了外部项目，
   都要在代码注释里写明来源，并在 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)
   汇总（项目名 / 作者 / 地址 / 许可证 / 具体借鉴内容）。
   提交信息正文同样要标注「借鉴自 <仓库>（作者，协议）：<内容>」。
   没有许可证的项目只参考行为与结论，不复制代码。
