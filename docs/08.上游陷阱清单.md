# 08. 上游陷阱清单

每一条都是实测踩出来的，改动前先读。

## 谷歌 Antigravity —— 凭证铁律

这是本项目踩坑最深的地方，**0.1.40→0.1.57 的「登录频繁失效」全是违反以下原则造成的**。

### 七条正确策略（现行实现）

1. **Provider 内部绝不主动刷新 Token**。`openChat`/`listModels`/`creditInfo` 只调
   `parse(account)` 取当前凭证。
2. **刷新唯一入口**：网关在每次请求前调 `provider.refreshAccount(account, settings.refreshSkewSeconds)`，
   而 `refreshAccount` 内部判断：只在 token 临期 5 分钟内（`REQUEST_SAFETY_WINDOW_SECONDS`）
   才真正调 OAuth。刷新频率天然 ≈ 1 小时 1 次。生效窗口 = `min(skewSeconds, 5min)`，
   故即使全局 `refreshSkewSeconds` 被配大也不会退化成每次请求都刷。
3. **刷新成功必须落盘**：`refreshAccount` 内通过
   `hooks.onAccountUpdated(toProviderAccount(refreshed, account))` 回存 ——
   Google 会轮换 refresh_token，不回存旧值作废后就是永久 `invalid_grant`。
4. **UID 稳定性**：`toProviderAccount(refreshed, existing)` 必须沿用既有账号的 uid，
   否则账号池键漂移 = 账号「消失」。
5. **classify 语义**：401/403 → `SESSION_DEAD`（硬禁用，提示重新登录）。**不要**降级成软重试 ——
   那会让账号很快回来再次触发刷新，形成刷新风暴加速风控。
6. **并发去重**：临期判断在锁外，故锁内必须复查「刚被别的线程刷出的凭证」
   （`lastRefreshed`，按 uid 缓存）并直接复用，否则同一窗口内 N 个在途请求会打出 N 次 OAuth。
   **命中缓存必须返回新凭证而非 null**，否则调用方拿旧 token 直接 401。
   重新登录（`exchangeCode`）要清该 uid 的缓存与冷却，防止旧凭证被回写。
7. **失败冷却**：刷新失败后 60s（`REFRESH_COOLDOWN_SECONDS`，按 uid）内不再重打 OAuth，
   避免 token 被吊销后按请求频率轰炸端点。

### 根因链条（为什么会有这七条）

Google 对同一个 refresh_token 的高频 token 换新有风控。0.1.53~0.1.57 曾在
每次对话前主动刷新 + 401 后「自愈重试」再刷 + 401 降级短冷却回来再刷 ——
三次叠加让一个 token 几分钟内被换新十几次，Google 直接吊销。
表现就是「反复需要重新登录」和后续的 503。

后续又发现两处残留放大器：`refreshAccount` 的临期判断在锁外、锁内不复查最新凭证
（并发 N 请求 = N 次 OAuth），以及刷新失败无退避（token 被吊销后 OAuth 频率 = 请求频率）。
两者均已按上面第 6/7 条堵住。

### 铁律

> 任何「让 Antigravity 更不容易掉线」的改动，如果最终效果是**增加了对
> `oauth2.googleapis.com/token` 的调用频率**，那它一定是错的，无论它看起来多有道理。

**不清空 `access_token`、不改写 `refresh_token`。** 上游用 refresh_token 轮换机制，
一旦你写了空值或把旧的写回去，下一次刷新就永久失效，只能重新登录。

### 另一个坑：对话与配额域名分离

| 用途 | 域名 |
|---|---|
| 对话 | `daily-cloudcode-pa.googleapis.com` |
| 配额查询 | `production-...` |

早期两处都打 daily，导致对话全量 429（daily 的配额小得多）。
配额查询只有 prod 给完整数据。

### 人机验证

需要验证时上游返回 403 `VALIDATION_REQUIRED` 并附 `validation_url`。
界面把它渲染成「一键去验证」，用 Custom Tabs 在应用内打开，验证完自动刷新额度。

## 腾讯（CodeBuddy）—— 强制流式

上游拒绝非流式请求。客户端要非流式时，网关按流式请求、本地聚合成普通 JSON。

### 成长任务的风控

「自动完成任务」有风控风险。埋点里的 `conversationId` 必须指向**真实发出的那次对话**，
自造 UUID 上游不认，进度不计。第一次建议先单条试，不要一上来就点批量。

## 字节（Trae）—— SOLO 私有通道

协议转换最重（15 个文件）。设备指纹用于签到校验，非数字格式会被上游拒绝。

## 讯飞（Loomy）—— HTTP 200 + 业务码

鉴权失败返回的是 **HTTP 200 + 业务码**，不是 4xx。
不判业务码就会把错误 JSON 当正常回复透传，用户看到一段莫名其妙的 JSON。

### 额度有两个账本

- `balance` 是永久账本
- `dailyBalance` 是当日赠送

可用总余额 = 主账本 + 当日剩余。只读一个会出现「额度包有 2992、余额还是一万」的不同步。

## 商汤（Raccoon）—— 响应包在 data 里

响应外层是 `{"status":..., "data":...}`，字段用标准名（不认 `max_new_tokens`）。

### 刷新策略三级兜底

不再沿用旧过期时间：响应时间 → JWT exp → 30 分钟兜底。
并发锁内复查 + 60 秒失败冷却 + 过期护盾（503 可重试，连续失败超 2 次放开）。

## 灵犀（mCloud）—— 加密请求体

普通接口（发码、登出、刷新 token）无国密，但请求体是
`Base64(IV‖AES-192-CBC)`。`thirdlogin` 是唯一特例（AES-128-ECB + 循环旋转）。

### 额度必须区分「未知」和「真的用光」

残缺 200（没有 `totalTokens`）不能当成 0——那会显示「额度 0」让人以为用完了。
用 `balanceKnown` 区分。

## Cline —— 三道门槛，缺一个就挂

### 1. `X-CLIENT-TYPE` 是免费池的硬门槛

缺了这个头，免费池模型一律 403（`only available via Cline product surfaces`）。
取值必须是 `cline-sdk` —— 写成 `cline-cli` 会让上游走另一条兼容路径，
回 `500 empty response content`，看起来像「模型坏了」。

### 2. `workos:` 前缀不能去掉

`Authorization: Bearer workos:eyJ...`，去掉前缀直接 401。
而 `/auth/refresh` 返回的 accessToken **不带**前缀（登录返回的带），
所以写入前必须统一补 —— 否则续期一次账号就废了。

### 3. `expiresAt` 同名不同型

桌面端 `providers.json` 里是**毫秒数**，`/auth/refresh` 返回的是 **ISO 8601 字符串**
（`"2026-09-19T19:30:04Z"`）。解析不分形态的话，续期一次就把过期时间读成 0，
之后每次请求都以为要刷新。

### 4. 余额路径的账号 id 叫 `external_id`

JWT 里是 `external_id`（`usr-...`），不是 `account_id`。取错字段的后果**不是报错**，
而是 uid 变成空串、路径拼成 `/users//balance`，上游回 `Invalid request format` ——
看起来像「协议写错了」，实际是 id 取错了。

### 5. 403 分两支，别一刀切成「凭证失效」

| 状态 | 归类 | 理由 |
|---|---|---|
| 403 + `ENTITLEMENT_ERROR` | `MODEL_LIMIT` | 这个号对这个模型没权限，换号可能有用 |
| 403 + 其它 | `SESSION_DEAD` | 确实可能是令牌问题 |

归 `SESSION_DEAD` 会硬禁用账号，用户得重新登录才能解封 —— 而权限问题重新登录解决不了。

### 6. 余额是微 credit，欠费是负值

`balance: -17704` 表示 **-0.0177 credit**（已欠费），要 ÷1e6。
上游 402 的文案会直接给出 `current_balance` 和 `buy_credits_url`，可以照抄给用户看。

> ⚠️ **两处口径不同，别混**：余额接口 `/users/{id}/balance` 的 `balance` 是**微 credit**
> （要 ÷1e6）；而 **402 错误体里的 `current_balance` 已经是 credit**
> （实测 `-0.002877`），再除 1e6 会显示成 -0.000002，看着像余额是 0。

### 7. 余额查询会因 token 过期而「拿不到账号 id」

`resolveUserId` 的三级兜底最后一环是 `GET /users/me`，而 token 过期时它回 **401**
（`Unauthorized: Please make sure you're using the latest version of Cline...`）——
于是 uid 取不到、如实报「拿不到账号 id」。

这不是协议错，是**凭证该续期了**。对话路径每次请求前都会 `refreshAccount` 保鲜，
所以对话正常、只有「刷新额度」会撞上（`refreshCredits` 刻意不保鲜）。
详见 [13.排查方法.md](13.排查方法.md) 的「已知坑」。

## 自定义供应商 —— 地址拼接

见 [04.供应商协议层.md](04.供应商协议层.md) 的「地址拼接」。

一句话：**不要先把 Base URL 尾部的 `/v1` 剥掉再贴协议路径**。
模型列表走固定 `/v1/models` 能拉到，对话却会被拼错，上游回
`The requested endpoint was not found`。

## 通用 —— 响应形状

| 现象 | 真实原因 |
|---|---|
| 200 但空 body | 代理吞响应 / 上游静默拒绝，不能当成功 |
| 200 但是 HTML | 登录页被当成了回复，不能透传 |
| 200 但 content 为空 | 空回复，要报可检测的失败 |
| 客户端要流式、上游只回 JSON | 包成 SSE，严格客户端才解析得出 |
