## 弹窗统一

改造前同时存在三种弹窗：Material3 `AlertDialog`（9 处）、自绘 `Dialog`（4 处）、
系统原生 `AlertDialog.Builder`（5 处）。三者圆角、内边距、标题字号、按钮排布各不相同。

现在全部走 `AppDialog`，只保证三件事：**同一套圆角与内边距、同一个标题样式、
同一套按钮位置（取消在左、确认在右）**。

### 尺寸约定

- 宽度固定 0.92（屏幕过宽时封顶）
- 高度不写死：内容少时自适应，内容多时封顶并在内部滚动

### 一个必须注意的点

`AppDialog` 默认 `scrollable = true`，会给内容套一层 `verticalScroll`。
它比 WebView 更早拿到拖动手势，**嵌 WebView 的弹窗必须显式传 `scrollable = false`**，
否则滑块拖不动（手指一滑整个弹窗在滚、滑块纹丝不动）。

## 导航栏

纯色扁平，配色全部来自 `MaterialTheme.colorScheme`，与 `PageHeader` 同源。

早期版本用 `isSystemInDarkTheme()` 跟随**系统**主题，导致 App 设「浅色」时
导航栏依然是黑的。现在跟随 App 自己的 `themeMode`。

## 账号卡片

### 「刷新额度」按钮只有一个

供应商详情页的「刷新额度」由**通用账号区**统一渲染
（`ProviderDetailScreen.kt`，条件是 `accounts.isNotEmpty() && !ui.managesOwnAccounts`）。

供应商自己的 `ProviderUi.AccountExtra` **不得再渲染第二个同名按钮** ——
同一页两个「刷新额度」点哪个都一样，纯属让人犹豫。

`managesOwnAccounts = true` 的供应商（腾讯 / 字节 / 自定义）自己渲染账号列表，
所以由它们各自提供那个唯一按钮。

`AccountCardShell` 的结构：

```
标题行（账号名 + 会员标签 + 改名图标 | 优先级箭头 + 启用开关）
extra（各供应商专属：额度、设备指纹、任务…）
footer（删除）
```

### 账号改名

点账号名弹出 `AccountRenameDialog`：

- 输入框默认填**自定义名本身**（没起过就是空），不是当前显示名
- 预填上游昵称的话，用户点开直接保存就会存成「自定义名 = 上游昵称」
- 留空 = 跟随上游，这条写在副标题里

## 自定义供应商表单

**新建与编辑共用同一个 Composable**。

早期详情页有一套与新建页不同的卡片，而新建页有协议下拉与余额预设——两边各自缺
另一半，用户看到的就是「新建时能选的功能，创建后就没了」。

现在两个入口渲染同一份卡片、同一套状态、同一段保存逻辑，功能天然一致。

### API Key 查看

已保存的供应商里，每个 Key 可以：

- 点「显示」看完整明文（默认遮住，截屏/录屏不泄漏）
- 点 Key 本身复制单个
- 「复制全部 Key（一行一个）」整组复制

**账号数必须读账号池**（`customAccountsWithKeys()`），不能读 `config.apiKeys`：
后者是「待同步的 Key」载体，保存成功后就清空了，读它永远显示 0，
会与下面「API Key（N 个）」卡片自相矛盾。

## 调用记录卡片：什么状态显示什么

卡片是**历史记录**，所以只承载「这次请求发生了什么」；任何**会过期的瞬态状态**都不进卡片。

| 元素 | 成功 · 路由 | 成功 · 故障转移 | 失败 | 中断 |
|---|---|---|---|---|
| 首行 | 模型名（客户端请求的，带标签）+ `成功` | 同 | 同 + `失败` | 同 + `中断` |
| 时间行 | `HH:mm:ss · 流式/非流式` | 同 | 同 | 同 |
| 指标行 | 耗时 / tokens / 命中 / 积分 | 同 | 耗时 + **上游状态码** | 耗时 / tokens |
| 供应商 · 账户行 | `[路由] 供应商 · 账户` | `[故障转移] 供应商 · 账户` | **不显示** | **不显示** |
| 故障账号行 | 只列路上折的号 | 同 | 列**所有**试过的号 | **不显示** |
| 模型行 | 仅当上游实际模型 ≠ 请求模型 | 同 | 同 | 同 |
| `禁用` 标签 | 该模型**当时**已禁用 | 同 | 同 | — |
| 熔断 / 冷却 | **不显示**（见下） | 同 | 同 | 同 |

### 四条不能违背的判据

1. **「路由 / 故障转移」看区域，不看换了几个号**。国内请求最终落在国内号上（哪怕中途换过几个）
   仍算路由，只有跨到另一个区域才算故障转移。判据是
   `routeRegion` 与 `finalAccountRegion` 的比较，两个都为空（非区域型供应商）时恒为路由。
2. **失败卡片没有「最终账号」**，所以不显示供应商·账户行 —— 结论是「都不行」，
   硬标一个「路由」只会让人困惑。试过的号统一进「故障」行。
3. **中断既不是成功也不是失败**：不打「故障」标签、不标红、不列账号。这里的账号只是
   「正在打的时候被中断了」，标红会让人误以为账号有问题。已产生的 token 照常显示（上游确实算钱）。
4. **熔断（供应商级、60 秒）与冷却（账号级、10 分钟）不进卡片**：两者都只存内存、瞬态会过期，
   写进历史记录，那条卡片过几分钟就开始说谎。要看「现在什么状态」去首页或供应商页；
   卡片里 `error` 字段已经写清了原因（如「该模型使用频率超限，约 19:26 后重置」）。
   只有**禁用**（24 小时、跨账号、落盘）进卡片，因为它是长期状态，写进历史是诚实的。

### 两个字段的分工

| 字段 | 含义 | 用途 |
|---|---|---|
| `model` | 客户端**请求**的模型（带路由标签） | 卡片标题 —— 用户要先对得上自己客户端的配置 |
| `resolvedModel` | 上游**实际收到**的模型（剥掉标签） | 只在两者**不同**时才显示一行（自定义供应商短名、上游重写等） |

`resolvedModel` 是后加的字段，旧记录读回空串 → 不显示那一行（不是「未知」，是「没必要说」）。

供应商名**不落库**，渲染时从供应商表解析（`state.providerOf(id)?.displayName ?: id`）——
省掉一次落盘格式变更，旧记录也照样显示。

### 请求日志要覆盖到什么

「请求日志」是运行日志（`RequestLog`，环形 300 行，文本行），它应当覆盖**所有会改变状态的操作**：

- 引擎层天然覆盖：转发、换号、额度刷新、登录、自动签到、设置变更、错误；
- **纯 UI 层的动作必须显式补一行**（它们不过引擎）：外观（动态取色 / 明暗模式 / 页面底色 /
  金色渐变 / 恢复默认）、保活（悬浮窗 / 实时状态通知）。补法是 `engine.noteForUser(...)`。

⚠️ **金色渐变记在去抖之后**：取色是拖动逐帧触发的，按帧写日志会把运行日志刷爆。
