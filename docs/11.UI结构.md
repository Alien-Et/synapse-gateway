## 弹窗统一

改造前同时存在三种弹窗：Material3 `AlertDialog`（9 处）、自绘 `Dialog`（4 处）、
系统原生 `AlertDialog.Builder`（5 处）。三者圆角、内边距、标题字号、按钮排布各不相同。

现在全部走 `AppDialog`，只保证三件事：**同一套圆角与内边距、同一个标题样式、
同一套按钮位置（取消在左、确认在右）**。

### 尺寸约定

- 宽度固定 0.92（屏幕过宽时封顶）
- 高度不写死：内容少时自适应，内容多时封顶并在内部滚动

### 一个必须注意的点

`AppDialog` 默认 `scrollable = true`，会给内容套一层 `verticalScroll`。
它比 WebView 更早拿到拖动手势，**嵌 WebView 的弹窗必须显式传 `scrollable = false`**，
否则滑块拖不动（手指一滑整个弹窗在滚、滑块纹丝不动）。

## 导航栏

纯色扁平，配色全部来自 `MaterialTheme.colorScheme`，与 `PageHeader` 同源。

早期版本用 `isSystemInDarkTheme()` 跟随**系统**主题，导致 App 设「浅色」时
导航栏依然是黑的。现在跟随 App 自己的 `themeMode`。

## 账号卡片

### 「刷新额度」按钮只有一个

供应商详情页的「刷新额度」由**通用账号区**统一渲染
（`ProviderDetailScreen.kt`，条件是 `accounts.isNotEmpty() && !ui.managesOwnAccounts`）。

供应商自己的 `ProviderUi.AccountExtra` **不得再渲染第二个同名按钮** ——
同一页两个「刷新额度」点哪个都一样，纯属让人犹豫。

`managesOwnAccounts = true` 的供应商（腾讯 / 字节 / 自定义）自己渲染账号列表，
所以由它们各自提供那个唯一按钮。

`AccountCardShell` 的结构：

```
标题行（账号名 + 会员标签 + 改名图标 | 优先级箭头 + 启用开关）
extra（各供应商专属：额度、设备指纹、任务…）
footer（删除）
```

### 账号改名

点账号名弹出 `AccountRenameDialog`：

- 输入框默认填**自定义名本身**（没起过就是空），不是当前显示名
- 预填上游昵称的话，用户点开直接保存就会存成「自定义名 = 上游昵称」
- 留空 = 跟随上游，这条写在副标题里

## 自定义供应商表单

**新建与编辑共用同一个 Composable**。

早期详情页有一套与新建页不同的卡片，而新建页有协议下拉与余额预设——两边各自缺
另一半，用户看到的就是「新建时能选的功能，创建后就没了」。

现在两个入口渲染同一份卡片、同一套状态、同一段保存逻辑，功能天然一致。

### API Key 查看

已保存的供应商里，每个 Key 可以：

- 点「显示」看完整明文（默认遮住，截屏/录屏不泄漏）
- 点 Key 本身复制单个
- 「复制全部 Key（一行一个）」整组复制

**账号数必须读账号池**（`customAccountsWithKeys()`），不能读 `config.apiKeys`：
后者是「待同步的 Key」载体，保存成功后就清空了，读它永远显示 0，
会与下面「API Key（N 个）」卡片自相矛盾。
