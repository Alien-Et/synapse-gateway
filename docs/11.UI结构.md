## 首页控制台

`HomeScreen.kt` 的网关状态卡展示「本机 / 局域网」两个接入地址。

- 局域网地址来自 `engine.lanUrls()`：只有接入设置打开「同时监听局域网」（`exposeLan`）
  才会枚举网卡地址；关闭时该方法直接返回空列表。
- 因此「局域网不可用」有两种语义，UI 必须区分，否则等于把用户往错方向引：
  - **监听未开启**：显示「监听未开启 · 点此到设置打开」，整行可点击，直达
    「接入设置」（`SubPage.ApiSettings`）——这是用户自己能解决的开关问题；
  - **已开启但无地址**（没连 Wi-Fi）：显示「未连接 Wi-Fi（局域网不可用）」——这是网络环境问题。
- 开关状态直接读 `AppUiState.settings.exposeLan`，不需要额外的状态字段。

## 弹窗统一

改造前同时存在三种弹窗：Material3 `AlertDialog`（9 处）、自绘 `Dialog`（4 处）、
系统原生 `AlertDialog.Builder`（5 处）。三者圆角、内边距、标题字号、按钮排布各不相同。

现在全部走 `AppDialog`，只保证三件事：**同一套圆角与内边距、同一个标题样式、
同一套按钮位置（取消在左、确认在右）**。

### 尺寸约定

- 宽度固定 0.92（屏幕过宽时封顶）
- 高度不写死：内容少时自适应，内容多时封顶并在内部滚动

### 一个必须注意的点

`AppDialog` 默认 `scrollable = true`，会给内容套一层 `verticalScroll`。
它比 WebView 更早拿到拖动手势，**嵌 WebView 的弹窗必须显式传 `scrollable = false`**，
否则滑块拖不动（手指一滑整个弹窗在滚、滑块纹丝不动）。

## 导航栏

纯色扁平，配色全部来自 `MaterialTheme.colorScheme`，与 `PageHeader` 同源。

早期版本用 `isSystemInDarkTheme()` 跟随**系统**主题，导致 App 设「浅色」时
导航栏依然是黑的。现在跟随 App 自己的 `themeMode`。

## 账号卡片

### 「刷新额度」按钮只有一个

供应商详情页的「刷新额度」由**通用账号区**统一渲染
（`ProviderDetailScreen.kt`，条件是 `accounts.isNotEmpty() && !ui.managesOwnAccounts`）。

供应商自己的 `ProviderUi.AccountExtra` **不得再渲染第二个同名按钮** ——
同一页两个「刷新额度」点哪个都一样，纯属让人犹豫。

`managesOwnAccounts = true` 的供应商（腾讯 / 字节 / 自定义）自己渲染账号列表，
所以由它们各自提供那个唯一按钮。

`AccountCardShell` 的结构：

```
标题行（账号名 + 会员标签 + 改名图标 | 优先级箭头 + 启用开关）
extra（各供应商专属：额度、设备指纹、任务…）
footer（删除）
```

### 账号改名

点账号名弹出 `AccountRenameDialog`：

- 输入框默认填**自定义名本身**（没起过就是空），不是当前显示名
- 预填上游昵称的话，用户点开直接保存就会存成「自定义名 = 上游昵称」
- 留空 = 跟随上游，这条写在副标题里

## 自定义供应商表单

**新建与编辑共用同一个 Composable**。

早期详情页有一套与新建页不同的卡片，而新建页有协议下拉与余额预设——两边各自缺
另一半，用户看到的就是「新建时能选的功能，创建后就没了」。

现在两个入口渲染同一份卡片、同一套状态、同一段保存逻辑，功能天然一致。

### API Key 查看

已保存的供应商里，每个 Key 可以：

- 点「显示」看完整明文（默认遮住，截屏/录屏不泄漏）
- 点 Key 本身复制单个
- 「复制全部 Key（一行一个）」整组复制

**账号数必须读账号池**（`customAccountsWithKeys()`），不能读 `config.apiKeys`：
后者是「待同步的 Key」载体，保存成功后就清空了，读它永远显示 0，
会与下面「API Key（N 个）」卡片自相矛盾。

## 模型页

### 头部四个按钮

| 位置 | 图标 | 行为 |
|---|---|---|
| 左 | ⏱（Speed） | 一键测速：全部模型并发探测，并发上限 4 |
| 中 | ⊘（Block，红） | 一键屏蔽：把测速失败的模型写进屏蔽名单；**只在真有失败结果时出现**，避免一个永远点不动的按钮 |
| 中 | 👁 / 👁‍🗨（Visibility / VisibilityOff） | 一键隐藏 / 恢复显示被屏蔽的模型；**只在真有屏蔽项时出现**，偏好写入加密本地设置，进程重启后保持 |
| 右 | ↻（Refresh） | 强制刷新目录（旋转动效只在加载中才创建无限过渡） |

「一键屏蔽」与「一键隐藏」都条件渲染是刻意的：没有失败结果 / 没有屏蔽项时它们无事可做，
一直亮着只会让人点一下、什么也没发生、然后怀疑功能坏了。

隐藏只是**列表过滤**，不改屏蔽状态：被隐藏的模型仍然在屏蔽名单里，也不参与路由。
某个分组被全部隐藏时，该分组下会显示一行「该分组的模型全部被屏蔽，点右上角眼睛图标可恢复显示」。

### 分组头统计

分组头分两行，统计简化为「可用比例 + 屏蔽数」：

```
⌃ 字节（国内） ●
  28/53 可用 · 屏蔽 23
```

- 第一行：折叠图标 + 供应商名 + 缓存/在线圆点
- 第二行：`测速成功数 / 该组模型总数 可用 · 屏蔽数`
- 分母是该组全部模型（包含被屏蔽、未测速的模型）；被屏蔽模型仍单独计数，不从分母剔除
- 不再单列「不可用」：模型尚未测速时失败数通常恒为 0；而测速失败也可能是限流或临时网络故障，直接标作不可用容易误导

**统计口径**：可用数只计入未屏蔽且最近一次测速成功的模型；被屏蔽数量独立显示。隐藏被屏蔽模型只过滤列表，不影响分组统计。

### 单行结构

```
模型 fullId + 复制图标 + 「已屏蔽」标签      [延迟]  [⊘ 屏蔽]  [测试]
副标题 / 能力 / 倍率 / 额度
失败：上游原文（整行宽度，最多两行）
```

- 整行点击 = 复制模型名
- 失败原因**单独占一行、放在模型下方**，点开 = 原生对话框看完整原文
- **被屏蔽的行整行 `alpha = 0.55`**：一眼能看出它不对外暴露；只降视觉不拦事件，
  ⊘ 按钮仍然可点，否则没法取消屏蔽
- 所有长度由上游决定的文本（模型名 / 副标题 / 能力 / 倍率 / 额度）都必须
  `maxLines = 1` + `Ellipsis`：Compose 的 Text 默认 `softWrap = true`，
  宽度不够时它会逐字换行而不是溢出——上游给一个 `computer_use_subagent` 这样的长名，
  整行就会变成一条竖着的字母柱

**失败原因为什么不能放在上面那行 Row 里**：它是一句上游原文，经常几十个字符。
塞进 Row 后 Compose 先测量固定宽度的子项（失败文本 + 两个按钮），左侧信息列只剩
极窄的剩余宽度，模型名与副标题随之竖排。放到下面独立一行、占满整行宽度，
就不会再挤压任何东西。这个坑踩过两次：第一次是模型名缺 `maxLines`，
第二次是副标题缺 `maxLines`，根因都是「宽度被挤到 1 个字符」。

### 列表容器

本页**不走 `PageScaffold`**：模型量大，用 `LazyColumn` 懒加载。
`PageScaffold` 的 `verticalScroll` 与 `LazyColumn` 不兼容（无限高度约束会崩）。

折叠状态用不可变 `Set` + `rememberSaveable`，不用 `SnapshotStateList`：
后者在保存时机被 `SaveableStateRegistry` 读取时若与 `LazyColumn` 的组合读快照交叠，
会抛「Reading a state that was created after the snapshot was taken」，表现为点折叠直接闪退。

## 调用记录卡片：什么状态显示什么

卡片是**历史记录**，所以只承载「这次请求发生了什么」；任何**会过期的瞬态状态**都不进卡片。

### 三层结构（方案 B）

卡片不再是「8 个垂直块全铺开」，而是分成三层：

| 层 | 内容 | 说明 |
|---|---|---|
| **左侧色条** | 绿（成功）/ 红（失败）/ 琥珀（中断） | 替代右上角状态徽章：省 40~50dp 横向空间，列表连起来看时成功/失败分布一眼可见 |
| **概览层**（永远可见） | 模型名 · 结果标签 · 账号摘要 · 关键指标 · 相对时间 | 扫视用；一屏能看到 6~7 条 |
| **展开层**（点击卡片就地展开） | 完整账号链路 · 上游模型 · 错误全文 · 请求/响应/上游报文原文 | 排查用；折叠不等于隐藏 |

### 概览层各元素

| 元素 | 成功 | 失败 | 中断 |
|---|---|---|---|
| 模型名 | 客户端请求的（带标签） | 同 | 同 |
| 结果标签 | **不显示**（绿条已说明） | `HTTP 502` 或 `失败` | `中断` |
| 账号摘要 | `供应商 · 账号`；跨区域时前缀 `故障转移 · ` | `3 个账号均失败`（单个时 `故障 · 账号`） | 不显示 |
| 指标 | 耗时 / tokens / 命中 / 积分 | 耗时（+ 状态码在结果标签里） | 耗时 / tokens |
| 相对时间 | `3分钟前` / `2小时前` / `昨天` / `3天前` | 同 | 同 |
| 错误摘要 | — | 单行截断（展开看全文） | — |
| `禁用` 标签 | 该模型当时已禁用 | 同 | — |
| 非流式 | 只在非流式时显示（流式是常态） | 同 | 同 |

### 滚动时自动切紧凑

手指滚动列表时，卡片自动收成**单行**（色条 + 模型名 + 耗时 + tokens + 相对时间），
停手 500ms 后恢复完整卡片。目的是一屏能扫过更多条记录。

- 判据用 `listState.isScrollInProgress` 而不是算速度：速度阈值在不同机型上手感差异大。
- 展开中的那条**永远不走紧凑**，否则用户点了展开却看到一行会很困惑。
- 同一时刻只允许展开一条：多条全展开会把列表撑成几屏，反而失去扫视意义。

### 四条不能违背的判据

1. **「路由 / 故障转移」看区域，不看换了几个号**。国内请求最终落在国内号上（哪怕中途换过几个）
   仍算路由，只有跨到另一个区域才算故障转移。判据是
   `routeRegion` 与 `finalAccountRegion` 的比较，两个都为空（非区域型供应商）时恒为路由。
2. **失败卡片没有「最终账号」**，所以概览层不显示供应商·账户，只给「N 个账号均失败」，
   具体是哪些号在展开区列出。
3. **中断既不是成功也不是失败**：不打「故障」标签、不标红、不列账号。这里的账号只是
   「正在打的时候被中断了」，标红会让人误以为账号有问题。已产生的 token 照常显示（上游确实算钱）。
4. **熔断（供应商级、60 秒）与冷却（账号级、10 分钟）不进卡片**：两者都只存内存、瞬态会过期，
   写进历史记录，那条卡片过几分钟就开始说谎。要看「现在什么状态」去首页或供应商页；
   卡片里 `error` 字段已经写清了原因（如「该模型使用频率超限，约 19:26 后重置」）。
   只有**禁用**（24 小时、跨账号、落盘）进卡片，因为它是长期状态，写进历史是诚实的。

### 两个字段的分工

| 字段 | 含义 | 用途 |
|---|---|---|
| `model` | 客户端**请求**的模型（带路由标签） | 卡片标题 —— 用户要先对得上自己客户端的配置 |
| `resolvedModel` | 上游**实际收到**的模型（剥掉标签） | 只在两者**不同**时才在展开区显示（自定义供应商短名、上游重写等） |

`resolvedModel` 是后加的字段，旧记录读回空串 → 不显示那一行（不是「未知」，是「没必要说」）。

供应商名**不落库**，渲染时从供应商表解析（`state.providerOf(id)?.displayName ?: id`）——
省掉一次落盘格式变更，旧记录也照样显示。

### 账号名同样动态解析（改名后立刻生效）

记录里存的是**历史快照**（`accountNickname` / `finalAccount` / `attemptedAccounts`），
而账号改名写入的是账号池的 `customName`。如果界面直接显示快照，就会出现
「改了账号名，但首页和记录页还是老名字」。

所以凡是**能定位到账号**的地方都按 `providerId + uid` 实时查当前账号，
用 `AccountStatus.displayName`（自定义名 > 上游昵称 > uid）：

| 位置 | 是否实时 | 原因 |
|---|---|---|
| 首页「最近路由记录 → 路由到」 | ✅ 实时 | 记录里有 `accountUid` |
| 记录页卡片「最终账号」 | ✅ 实时 | 同上 |
| 记录页展开区「最终账号」 | ✅ 实时 | 同上 |
| 记录页展开区「账号链路」/「失败过」 | ❌ 历史快照 | `attemptedAccounts` 只存昵称，没有 uid，无法反查 |

要修最后一行得给 `attemptedAccounts` 加存 uid（改落盘格式，旧记录仍回落到快照）。
目前没做——那条链路主要用于看「这次试了哪些号」，昵称足够定位。

### 原文按需加载

概览层只持有截断摘要；请求/响应/上游报文的完整原文可能几十万字符，
**展开时才读盘**（`CallLogStore.fullText`），且默认只渲染前 6 行、点标题展开全文。
复制按钮始终可用，不需要先展开。

### 请求日志卡片

请求日志（Requests 标签）的卡片**固定高度、只放概要**：

```
14:23:05  [INFO]  转发 → 上游 200（剩余 12345）
```

- 时间（等宽）+ 级别徽章（按级别上色）+ **首行摘要**（`maxLines = 1` + Ellipsis）
- 点卡片 → 底部浮窗看**完整正文**（保留换行、等宽字体）+ 一键复制
- 卡片高度不随内容变化：旧实现直接塞 `line.render()`，一条几十行的 JSON 能把列表撑出一屏高

调用记录（Calls 标签）的卡片结构不同，见 [10.额度与用量统计.md](10.额度与用量统计.md)。

### 请求日志要覆盖到什么

「请求日志」是运行日志（`RequestLog`，环形 300 行，文本行），它应当覆盖**所有会改变状态的操作**：

- 引擎层天然覆盖：转发、换号、额度刷新、登录、自动签到、设置变更、错误；
- **纯 UI 层的动作必须显式补一行**（它们不过引擎）：外观（动态取色 / 明暗模式 / 页面底色 /
  金色渐变 / 恢复默认）、保活（悬浮窗 / 实时状态通知）。补法是 `engine.noteForUser(...)`。

⚠️ **金色渐变记在去抖之后**：取色是拖动逐帧触发的，按帧写日志会把运行日志刷爆。
