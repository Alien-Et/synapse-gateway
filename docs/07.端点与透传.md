# 07. 端点与透传

## 端点目录

全部集中在 `provider/ApiEndpoints.kt`。新增端点只改这一处，路由、provider 能力声明、
界面上的「支持哪些接口」全都从这里取。

### 两类端点

| 类型 | 走哪条链路 |
|---|---|
| `CHAT` | 完整选号 + 容灾 + 流式透传（`openChat`） |
| `PASSTHROUGH` | 选一个可用账号，原样转发（`passthrough`），不重试 |

## 为什么透传端点不做容灾

生图、语音都是**计费**动作。失败换号重试会出现「同一张图扣两次钱」。

所以这些端点只选一个可用账号发出去，失败就如实报错，不自动重试。

## 为什么响应体不改写

图片是 base64、语音是二进制、向量是浮点数组。任何「解析再序列化」都可能损坏内容
（浮点精度、base64 换行、二进制编码）。

所以 passthrough 拿到什么就返回什么，只有 `Content-Type` 用来判断是不是二进制流。

## requiresModel 的作用

有些端点请求体里没有 `model`（语音转写、语音合成、模型列表）。这些端点标
`requiresModel = false`，选供应商时不强制要求 body 里有模型名。

早期版本对无 model 的端点也强制校验，导致「语音合成用不了」。

## 模型测试的端点分流

「测试」按钮会按模型类型打对应端点，不再一律发对话请求。识别逻辑见
[04.供应商协议层.md](04.供应商协议层.md) 的「模型端点识别」。

| 模型类型 | 测试端点 |
|---|---|
| 对话 | `/v1/chat/completions` |
| 图片生成 | `/v1/images/generations` |
| 视频生成 | `/v1/videos/generations` |
| 文本向量 | `/v1/embeddings` |
| 重排 | `/v1/rerank` |
| 语音合成 | `/v1/audio/speech` |
| 语音转写 | **无法测试**（要上传音频），界面直接说明 |
