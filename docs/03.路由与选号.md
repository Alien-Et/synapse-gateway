# 03. 路由与选号

## 路由：标签是唯一依据

模型名写成 `标签/模型名`，标签唯一确定一家供应商。

```
标签/模型名
```

| 标签 | 供应商 | 区域 |
|---|---|---|
| `腾讯国内/` | 腾讯 | cn |
| `腾讯国外/` | 腾讯 | global |
| `字节国内/` | 字节 | cn |
| `字节国外/` | 字节 | global |
| `谷歌/` | 谷歌 | — |
| `讯飞/` | 讯飞 | — |
| `商汤/` | 商汤 | — |
| `灵犀/` | 灵犀 | — |
| `<自定义标签>/` | 自定义供应商 | — |

### 判定流程

```
resolveRoute(model)
  ├─ 剥掉 "models/" 前缀
  ├─ 没有 "/"                       → 400 model_not_routable
  ├─ 标签不在表中                   → 400 model_not_routable
  ├─ 供应商未注册 / 未启用 / 无账号 → 报具体原因
  └─ 全部通过                       → Route(供应商, 模型, 区域)
```

**不查目录、不推断名称、不兜底给别家。** 写 `腾讯国内/qwen-max` 只会发到腾讯，
即使 qwen 实际在字节。写错标签时上游会如实报「没这个模型」——该改标签，别期待网关猜。

### 为什么不做「智能匹配」

上游仓库曾试过「按模型名自动找同款模型」，结果是把用户的请求偷偷改发到了另一家：
用户写 `字节国内/xxx`，字节撞错后静静跑去谷歌。这与「标签绑定供应商」直接冲突，已移除。

## 选号：同家内部挑账号

`AccountPool.pick()` 的优先级：

1. **排除**本轮已试过的 uid（同一请求内的换号重试）
2. **排除**不可用账号（`disabled` 硬禁用 或 `enabled=false` 手动停用）
3. **跳过**已知额度为 0 的账号（仅第一轮；见下）
4. 按**优先级**降序（用户 ↑/↓ 手动排的）
5. 同优先级按**余额**降序

### 为什么「已知额度为 0」只在第一轮跳过

池里的额度是**上次刷新时的快照**，不是实时值。无条件按它过滤，一个早上刚充值
的账号会被永久跳过，看上去就是「明明有额度却总是不用它」。

所以规则是：

- 同一请求的**第一轮**开启跳过，避免明知为空还白打一次上游；
- 第一轮全部跳过/失败后的**补位轮关闭跳过**，让「余额记录过时」有机会被真的纠正
  ——真没额度的话，上游会报 `QUOTA`，那一刻才真正知道它空。

## 区域：硬约束 + 可选跨区

腾讯和字节各有国内站与国外站，各是一池账号。

```
请求 腾讯国内/glm-5.2
  → 先在国内号里找
  → 国内号全部不可用
  → 【跨区域开关开着】顺延到国外号
  → 【关着】直接报错
```

默认开启跨区域。**优先级严格保证**：先在本区域找，本区域一个可用账号都没有时才跨区。
绝不会因为国外号余额更高就先跑国外。

## 调用记录里怎么区分

| 卡片显示 | 含义 |
|---|---|
| `[路由] [● 账号A]` | 一次就成 |
| `[故障转移] [● 账号A]` + 下方 `[故障] [● 账号B]` | 账号 B 失败后换到账号 A |
| `[失败]` + 下方多个 `[故障] [● 账号]` | 所有账号都试过，全都不行 |

**判定看区域，不看换了几个号**：

| 请求 | 最终用的账号 | 标签 |
|---|---|---|
| `腾讯国内/x` | 国内号 | 路由（哪怕中途换过几个国内号） |
| `腾讯国内/x` | 国外号 | **故障转移** |
