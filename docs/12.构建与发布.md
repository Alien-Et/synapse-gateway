# 12. 构建与发布

## 本地构建

```sh
./gradlew :app:assembleDebug --console=plain   # debug 包，包名与 release 一致
./gradlew :core:test --console=plain           # 单元测试
./gradlew :cli:installDist --console=plain     # 命令行工具
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

本地 debug 与云端 release 使用**同一套 keystore**，可互相覆盖升级，配置不丢。

**编译前先清理历史产物**（`app/build/outputs/apk/debug`），避免误装旧包。

## 发版：打标签即完成

版本号由标签决定，**不需要先改文件**：

```sh
git tag -a v3.0.8 -m "v3.0.8"
git push origin v3.0.8
```

工作流自动完成：

1. 把标签版本写进 `build.gradle.kts`（`versionName` 取标签，`versionCode` 自动递增）
2. 跑单元测试
3. 打签名 release 包
4. 创建 GitHub Release，上传 `synapse-<版本>-release.apk`
5. 把版本号同步回 main

### 标签规则

**按仓库已有标签序列递增**，不要拿 APK 的 `versionName` / `versionCode` 当标签名。

打标签前先查：

```sh
git ls-remote --tags origin
```

当前序列：`v3.0.0` → `v3.0.2` → … → `v3.0.7`。

标签必须是纯 `v<主>.<次>.<修订>` 三段数字，`v3.0.1-beta` 会被拒绝。

### 推送前先 fetch

每次打标签发布后，CI 都会往 main 推一个「同步版本号」提交。下次推送前先：

```sh
git fetch origin main
```

避免被非快进挡住。**绝不盲目强推。**

## 工作流

| 工作流 | 触发 | 作用 |
|---|---|---|
| `android-release.yml` | push `v*` 标签 / 手动 | 测试 → 打包 → 发 Release → 同步版本号 |
| `build-release.yml` | 手动 | 只测试 + 打包，产物作为 artifact |

## Secrets

需配置 4 个：

- `KEYSTORE_BASE64`
- `KEYSTORE_PASSWORD`
- `KEY_ALIAS`
- `KEY_PASSWORD`

```sh
base64 -w0 release.keystore > keystore.b64
```

工作流的 build-tools 版本需与 `app/build.gradle.kts` 的 `buildToolsVersion` 一致
（当前 `36.0.0`）。

## 在 ARM64 手机上构建

本项目在 Android 手机上用 proot 沙箱构建，需要三个前提：

1. **ARM 版 NDK** —— 官方 x86_64 NDK 会报 `exec format error`
2. **ARM 版 aapt2** —— 通过 `aapt2FromMavenOverride` 指向 ARM 版二进制
3. **Gradle 配置** —— `ANDROID_NDK_ROOT` 指向 ARM NDK

细节见 `/skills/android-sdk-arm64/`、`/skills/android-arm-ndk/`、
`/skills/flutter-arm-build/`。

## 安装验证

```sh
# root 覆盖安装（沙箱路径必须用手机真实路径）
np_apk_install apkPaths=["/data/user/0/<包名>/files/workspaces/<id>/files/xxx.apk"]
```

验证三件事：

1. `dumpsys package io.synapse.app` 看 versionCode / versionName
2. 截图看界面正常
3. `logcat` level=E + DropBox crash report 确认零崩溃、零 ANR
